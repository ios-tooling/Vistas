# Repository Guidelines

## Project Structure & Module Organization
- `VistasTestHarness/` contains the Xcode project folder.
- `VistasTestHarness/VistasTestHarness/` is the app target source code (SwiftUI).
- `VistasTestHarness/VistasTestHarness/Assets.xcassets` stores image and color assets.
- `VistasTestHarness/Products/` contains build artifacts (generated by Xcode).

## Build, Test, and Development Commands
- Build in Xcode: open the project and use Product > Build to compile the app.
- CLI build (example):
  ```sh
  xcodebuild -scheme VistasTestHarness -destination 'platform=iOS Simulator,name=iPhone 15' build
  ```
  Builds the app for the simulator; adjust destination as needed.
- Run locally: use Xcode Product > Run to launch on a simulator or device.

## Coding Style & Naming Conventions
- SwiftUI-first; keep views small and focused on a single responsibility.
- Indentation: 4 spaces.
- Naming: PascalCase for types, camelCase for properties and methods.
- Prefer `@State private var` for view state and `let` for constants.
- Avoid force unwraps; lean on Swift’s type system.

## Testing Guidelines
- No test targets are currently present. If adding tests, use the Testing framework for unit tests and XCUIAutomation for UI tests.
- Name tests with clear intent, e.g., `testCameraCaptureSavesThumbnail()`.

## Commit & Pull Request Guidelines
- Commit messages in history are short, lowercase, and action-oriented (e.g., “added Test Harness”). Follow this pattern.
- Pull requests should include:
  - A concise summary of changes and motivation.
  - Screenshots or screen recordings for UI changes.
  - Linked issues or tickets, if applicable.

## Agent-Specific Notes
- Limit changes to the requested task scope.
- Prefer Xcode tooling for project inspection and builds.
- Avoid touching generated artifacts under `VistasTestHarness/Products/`.
